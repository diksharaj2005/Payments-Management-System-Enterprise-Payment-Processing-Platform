11 · ENGINEERING DECISIONS

Why the architecture is shaped this way.

Factory + Strategy for gateway extensibility

Provider selection is separated from payment orchestration so a new gateway can be introduced without rewriting the core payment flow.

PaymentService → GatewayProviderPaymentApiClientFactory → SETU Adapter

Ledger as the accounting source of truth

Payment state and accounting state are connected through explicit ledger transactions, line items and balance validation.

Transaction → DEBIT ₹10,000 + CREDIT ₹10,000 → VALID

Asynchronous confirmation

Webhook-driven events decouple external provider callbacks from downstream processing, with status tracking and failure-handling paths.

WEBHOOK → EVENT → PROCESSING → COMPLETED / DEAD LETTER

Concurrency control

Optimistic locking helps protect shared financial records when concurrent workers attempt to update the same account state.

ACCOUNT v7 → Worker A ✓ → Worker B conflict → ACCOUNT v8
11 · SECURITY & QUALITY

Encrypted credentials

Gateway connection settings are stored using encrypted configuration handling.

Input validation

Bean validation protects API boundaries before business logic runs.

Safe errors

Exception handling avoids leaking stack traces through API responses.

JPA parameterization

Repository/data-access abstractions avoid handwritten unsafe SQL for normal operations.

Automated tests

CI / CodeQL
